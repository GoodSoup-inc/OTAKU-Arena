# Agile Methodology Reflection

## Prompt

As a group, answer the questions below. For each of these questions, consider specific examples to support your narrative.

- Reflect on your team's communication processes. How did Agile practices, such as **daily stand-up** meetings, facilitate communication and collaboration among team members?
- How did maintaining a **scrum board** play a role in the organization and delegation of tasks in your project?
- Reflect on your team's prioritization of tasks. How did your team create a **timeline for reaching MVP** and how did this prioritization assist in accomplishing your goals?
- What would you have done differently as a group to improve your communication, prioritization, or delegation of tasks?

**Write your reflection using markdown**.

## Reflection Response

- During this project, the agile practices that we used were frequent meetings together as well as update messages in between if we were unable to communicate. This most definitely played a major factor in the flawless workflow of the group. After every meeting, we were able to effectively make more progress in the development of the project. When meetings were not able to be held, notes written within the code allowed each team member to understand each process of the development, as well as make sure that each group member wasn't working on the same task at the same time. Also message updates through the process allowed for the group always to be updated on new features that were made or removed, while also allowing the group to ask clarifying questions about project development that couldn't be answered by the scrum board.
- The scrum board, while it was effective to list out the development tasks, and the deadline for them, we found that the scrum board was less helpful throughout the process. During this project because the communication was so effective the group would update the scum board less and less every day because of how quickly we would create, disgraced, or completely change the ideas that we first created.
- While the group was not effective with using the scum broad prioritization our tasks never faltered. As a group, functionality was the main priority. We both would work on getting our user actions to work completely first without interruption before allowing us to fall into the project's CSS. If one day either of us were not able to complete our tasks we would work on getting help from each other to help keep on track of the development.
- As a group, we believe that our communication and the tasks we prioritized were highly efficient and effective for the completion of this project. Although it is recognized that we should have utilized our scrum board a lot more in order to better keep track of extra ideas we wanted to create or ideas that we already disregard as a way to not repeat certain steps.
